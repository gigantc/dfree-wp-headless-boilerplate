# dFree's Headless WordPress Boilerplate

Sister to [dFree's PHP theme boilerplate](https://github.com/…) — the same
folder taxonomy, the same vocabulary, the same block/component mental model.
Choose the traditional stack or the headless stack, and the way you think
about the code stays the same.

## What's This Thing Do?

A Next.js 16 + TypeScript + WPGraphQL boilerplate for building headless
WordPress sites. Blocks are React Server Components that render on the server,
resolved from a `manifest.json` that mirrors the PHP theme's block registry.

## Quick Start

### Prerequisites

- Node 20+
- A WordPress install with:
  - [WPGraphQL](https://wordpress.org/plugins/wp-graphql/)
  - [WPGraphQL for ACF](https://github.com/wp-graphql/wpgraphql-acf)
  - [WP GraphQL Content Blocks](https://github.com/wpengine/wp-graphql-content-blocks)
  - Advanced Custom Fields Pro (or free, if the fields you need are supported)
  - Any theme (Twenty Twenty-Five is fine — this is headless, the WP theme
    never renders on the frontend)

### Get It Running

```bash
# 1. Install dependencies
npm install

# 2. Configure your WordPress endpoint
cp .env.local.example .env.local
# Edit .env.local — set WORDPRESS_GRAPHQL_ENDPOINT and NEXT_PUBLIC_WORDPRESS_URL

# 3. Generate WPGraphQL types (once, or after schema changes)
npm run codegen

# 4. Start dev server
npm run dev
```

## How the Block System Works

### The Convention

An ACF block registered on the WP side with name `acf/hero-page` is rendered
by the file at `blocks/{category}/HeroPage/HeroPage.tsx`. The category comes
from the manifest, which is auto-generated by walking the folder tree.

### The Magic Behind It

1. WordPress serves any URI. `app/[[...slug]]/page.tsx` asks WPGraphQL for
   `nodeByUri` — a single query that returns any page, post, or CPT.
2. The response includes `blocksRaw` — the block data as JSON.
3. `<BlockRenderer>` (an RSC in `lib/blocks/renderer.tsx`) walks each block,
   looks up the component in `blocks/manifest.json`, dynamically imports it on
   the server, and passes shaped ACF props.
4. Output is fully-rendered HTML. No client-side hydration for content — only
   for components that opt in with `"use client"`.

### Creating Your First Block

```bash
mkdir -p blocks/hero/MyHero
```

Create three files:

**`blocks/hero/MyHero/MyHero.tsx`**
```tsx
import styles from "./MyHero.module.scss";

type Props = { title?: string };

export default function MyHero({ title }: Props) {
  return <section className={styles.hero}><h1>{title}</h1></section>;
}
```

**`blocks/hero/MyHero/MyHero.module.scss`**
```scss
@use "styles/variables" as v;
.hero { padding: 80px 0; background: v.$black; color: v.$white; }
```

**`blocks/hero/MyHero/block.config.json`**
```json
{
  "title": "My Hero",
  "description": "A custom hero block.",
  "keywords": ["hero"],
  "requires": []
}
```

Then on the WP side, register an ACF block with name `my-hero` (matching the
kebab-case of the folder name). The manifest regenerates on next `npm run dev`.

## Block Organization

See [`docs/block-folder-structure.md`](docs/block-folder-structure.md) —
matches the sister PHP theme exactly. Top-level folders: `layout/`, `hero/`,
`feature/`, `utility/`, `misc/`.

## Component System

Shared UI atoms live in `components/`. Unlike the PHP theme's `component()`
render helper, JS uses native imports. The manifest is generated for tooling,
not for the render path.

See [`docs/component-folder-structure.md`](docs/component-folder-structure.md).

## Build System

- **Next 16** with App Router, RSC, Turbopack.
- **TypeScript** everywhere. `graphql-codegen` generates types from your
  WPGraphQL schema.
- **SCSS Modules** for block/component styles. Global styles in `styles/`.
- **Manifests** auto-generate before `dev` and `build` (see `predev` /
  `prebuild` scripts). Add `npm run manifests:watch` in a separate terminal
  during heavy block authoring.

## WordPress-Side Requirements

This repo is frontend-only. The WordPress install needs:

1. **Plugins** — WPGraphQL, WPGraphQL for ACF, WP GraphQL Content Blocks, ACF Pro.
2. **ACF block registrations** — each block registered via `acf_register_block_type()`
   with a name matching a folder here (`hero-page` → `blocks/hero/HeroPage/`).
   Recommended: live in a small mu-plugin so the active WP theme stays vanilla.
3. **CORS / GraphQL access** — WPGraphQL allows public queries by default;
   configure auth if you need protected fields.
4. **Menu locations** — register with `register_nav_menus()` in the mu-plugin.

A companion `dfree-wp-headless-mu-plugin` repo will handle #2 and #4 (TBD).

## Deployment

Static-first: `next build` produces a mix of statically-generated and
server-rendered routes. Deploy to Vercel, Cloudflare Pages, or any Node host.
Set env vars for `WORDPRESS_GRAPHQL_ENDPOINT`, `NEXT_PUBLIC_WORDPRESS_URL`,
and `WORDPRESS_PREVIEW_SECRET`.

Set `revalidate` on individual queries (`lib/wp/client.ts`) to control the
ISR cache TTL per query.
